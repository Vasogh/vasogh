# Бахчисарай.NET — смартфоны с лентами ВК и Telegram

## Что подготовлено

- Два смартфона под главным блоком: рядом на компьютере, друг под другом на телефоне.
- ВК: официальный виджет стены, который получает публикации непосредственно из ВК.
- Telegram: последние 8 публикаций через официальные виджеты. Отдельный бот собирает номера новых постов; GitHub Actions сохраняет ленту и публикует сайт по расписанию каждые 15 минут.
- Круглые кнопки соцсетей с увеличенными логотипами, подсветкой и покачиванием при наведении.
- Добавленные ветки, переключатель анимации и Instagram отсутствуют.

Это готовый код для подключения, но интеграция ещё не активирована на вашем аккаунте. ID группы ВК уже указан. Нужен токен отдельного Telegram-бота в защищённых настройках GitHub. В архиве нет выдуманных публикаций: до подключения в смартфонах видны ссылки на сообщества.

## Подключение один раз

### 1. ВКонтакте уже настроен

ID вашей группы — 54260440. Он подтверждён предоставленной ссылкой https://vk.ru/wall-54260440_1878048 и уже указан в data/config.json. Дополнительные настройки ВК и токен не нужны.

Если вы ранее создавали Variable VK_GROUP_ID в GitHub, убедитесь, что в ней также стоит 54260440, или удалите её: переменная имеет приоритет над файлом. Работу самого виджета нужно проверить после загрузки сайта.

### 2. Создайте отдельного Telegram-бота

Откройте https://t.me/BotFather (официальный бот Telegram) → отправьте /newbot → задайте имя и свободное имя пользователя, заканчивающееся на bot.

Сохраните выданный токен. Не отправляйте его в чат и не добавляйте в файлы репозитория.

Добавьте бота администратором в канал @bahchisarai. Для чтения постов ему не нужны права публиковать, редактировать или удалять записи: отключите эти и другие ненужные разрешения, которые позволяет интерфейс Telegram. Код только читает события канала и не публикует ничего в Telegram.

Используйте нового бота только для этого сайта. Не подключайте его одновременно к конструкторам ботов, другим программам, webhook или ещё одному опросу getUpdates. Если обнаружится существующий webhook, скрипт остановится, не изменяя его.

### 3. Сохраните токен в GitHub

Репозиторий vasogh/vasogh → Settings → Secrets and variables → Actions → Secrets → New repository secret.

Name: TELEGRAM_BOT_TOKEN
Secret: токен из BotFather.

Сохраните. Это именно Secret, а не обычная Variable. Скрипт получает его только во время запуска. В браузер посетителя и публичные файлы токен не попадает.

### 4. Выберите способ публикации

Settings → Pages → Build and deployment → Source → GitHub Actions.

Custom domain оставьте текущим. CNAME и DNS в REG.ru не меняйте. Переключение Source нужно только один раз для автоматической публикации этой версии.

### 5. Загрузите содержимое архива

Распакуйте ZIP. В репозитории откройте Code → Add file → Upload files.

Загрузите файлы и папки из архива в корень репозитория, сохраняя структуру. Важно, чтобы файл автоматизации попал по точному пути:

.github/workflows/site.yml

Также нужны index.html, style.css, feeds.js, папки assets, data и scripts. Не загружайте ZIP вместо распакованных файлов и не помещайте сайт в дополнительную вложенную папку.

Нажмите Commit changes. Если папка автоматизации не загрузилась, используйте Add file → Create new file, введите .github/workflows/site.yml и вставьте содержимое одноимённого файла из архива.

Важно: первоначальный data/telegram.json в архиве пустой. После запуска интеграции не заменяйте накопленный data/telegram.json этим пустым файлом при будущих обновлениях дизайна. Состояние data/telegram-state.json также нужно сохранять.

### 6. Первый запуск

Откройте Actions → Update feeds and publish site. После загрузки код запускается автоматически. Для ручного запуска: Run workflow → main → Run workflow.

Дождитесь зелёного статуса и обновите сайт. ВК должен показать стену с уже указанным ID группы.

Опубликуйте обычную новую запись в Telegram после добавления бота. Нажмите Run workflow ещё раз либо дождитесь расписания. В смартфоне появится публикация. Бот не получает всю старую историю канала автоматически; наполнение начинается с новых постов после подключения.

Проверьте сайт на ноутбуке и телефоне: обе ленты, ссылки на сообщества, прокрутку и круглые кнопки.

## Что будет происходить автоматически

ВК загружает стену при открытии страницы. Telegram проверяется в минуты 07, 22, 37 и 52 каждого часа. Затем GitHub публикует обновлённую страницу. Это ориентировочно 15 минут плюс время запуска и публикации; GitHub может задерживать или пропускать запуски при нагрузке. Уже открытая вкладка не обновляет ленту сама: для новых записей обновите страницу.

В Telegram показываются 8 последних полученных публикаций, новые сверху. Альбомы объединяются. Текст и медиа отображает официальный виджет Telegram; особые типы публикаций могут требовать перехода в приложение. Изменения содержания определяются самим виджетом. Удаления обычных постов не поступают через этот механизм: удалённая запись может временно остаться недоступным блоком до вытеснения новыми постами.

ВК и Telegram должны быть доступны из браузера посетителя. Если сервис или его виджет заблокирован, расширение мешает загрузке или есть сбой сети, останутся прямые ссылки. Сам сайт не обходит ограничения доступа к соцсетям.

## Стоимость и ограничения

Используются GitHub Pages и стандартные Linux runners GitHub Actions в публичном репозитории. Согласно документации GitHub, такие runners бесплатны для публичных репозиториев. Платные larger runners и сторонние подписки здесь не используются. При переводе репозитория в private нужно отдельно проверить тариф и лимиты.

Обычная публикация новостей больше не требует правок сайта. Однако это не гарантия бессрочной работы без обслуживания:

- Telegram хранит недоставленные события не более 24 часов. Если автоматизация не работает дольше суток, часть постов может быть пропущена. При ошибках смотрите Actions; предыдущая опубликованная версия сайта остаётся доступной.
- Расписание публичного репозитория отключается после 60 дней без активности репозитория. Обновления ленты создают коммиты, но после длительного отсутствия публикаций проверьте Actions и при необходимости включите workflow.
- Для автоматического сохранения данных workflow должен иметь право записи в main. Защита ветки может блокировать этот шаг. Не отключайте правила защиты вслепую: сначала посмотрите конкретную ошибку.
- Настройки GitHub, доступность соцсетей и API могут меняться.

## Если что-то не работает

Actions с ошибкой: откройте последний запуск и шаг с красным крестиком.

- TELEGRAM_BOT_TOKEN is missing: добавьте Secret с точным именем.
- HTTP 401: проверьте токен; при необходимости перевыпустите его у BotFather и обновите Secret.
- HTTP 400 / Expected public channel not found: проверьте, добавлен ли бот в канал @bahchisarai.
- HTTP 409 / already uses a webhook: используйте отдельного нового бота; текущий бот может быть занят другим сервисом.
- Ошибка git push: проверьте права Actions и правила ветки. Токен GitHub вручную в код не добавляйте.
- Ошибка Deploy: проверьте Source = GitHub Actions в Settings → Pages.
- ВК показывает ссылку вместо стены: проверьте Variable VK_GROUP_ID и повторно запустите workflow; затем проверьте доступность ВК/блокировщики в браузере.
- Telegram пустой: опубликуйте новый пост после добавления бота и повторите запуск. Проверьте, что в data/telegram.json появились номера постов.

## Проверки и локальный просмотр

Обработчик протестирован на повторных событиях, чужом канале, альбомах, редактировании, ограничении длины ленты и служебных сообщениях. Настоящий токен не использовался. Визуальный просмотр в браузере в среде подготовки не выполнен: браузер не удалось установить. Полная проверка реальных виджетов и публикации возможна после подключения в вашем GitHub.

Для локального просмотра запустите в папке проекта python3 -m http.server 8000 и откройте http://localhost:8000. Открытие через file:// не поддерживает загрузку JSON-лент во многих браузерах. Секретные данные локально вводить не нужно.
